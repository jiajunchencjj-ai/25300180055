    - 思考一下，Git 为什么要设计“暂存-提交”两个步骤？    

    **在工作区里，可能会有多个文件进行了修改。如果不设计暂存的途径，直接提交可能会使修改的历史记录较为混乱，不方便检查。而有了暂存区，我们可以筛选想要提交的修改并上交，这种分组化的修改方式能够更精准地查阅到每次修改的历史记录，减少提交的次数，版本更新更精确。同时，暂存区使我们能再次核查修改内容，以避免无效的版本控制。**
      
    - `git branch` 和 `git branch -a` 的区别是什么？查阅资料并回答。    

    **区别是`git branch` 和 `git branch -a` 显示的分支范围不同。
git branch 只会显示本地分支，也就是当前仓库中已经创建并存在于本地的分支。当前所在的分支前面通常会有一个 * 号。  
git branch -a 中的 -a 是 --all 的缩写，它会显示所有分支，包括本地分支和远程跟踪分支。
git branch -a 显示的远程分支信息来自本地保存的远程仓库状态，并不是每次执行都会实时访问远程仓库。**

3. 在下面的三个网页中任选其二进行阅读，简要概括其内容，并谈谈你对“为什么要学习 Git”这个问题的理解。（15 分）

    - [Commit Message 规范](https://www.ruanyifeng.com/blog/2016/01/commit_message_change_log.html)
    - [Git Flow 分支控制](https://www.dafaycoding.com/article/git-gif-flow)
    - [语义化版本](https://semver.org/lang/zh-CN/)

    我选择阅读了《Commit Message 规范》和《语义化版本》两篇文章。

《Commit Message 规范》主要介绍了 Git 提交信息的作用和规范写法。规范的 Commit Message 可以帮助开发者清楚地了解代码的修改历史，也便于后续查看、筛选提交记录和生成 Change Log。文章还介绍了一套较完整的提交信息规范——Angular，并说明可以借助相关工具如Commitizen、validate-commit-msg来生成和检查提交信息。

《语义化版本》主要介绍了软件版本号的规范。语义化版本通常采用 `主版本号.次版本号.修订号`，也就是 `X.Y.Z` 的形式。当软件进行了不兼容的修改时增加主版本号；增加了向下兼容的新功能时增加次版本号；只进行了向下兼容的问题修复时增加修订号。通过这种规范，可以让开发者仅通过版本号就大致判断软件发生了什么程度的变化，同时也有利于解决多人开发和软件依赖中的版本混乱问题。

阅读这两篇文章以后，我对“为什么要学习 Git”有了更具体的理解。刚开始我并不了解Git的具体功能和作用，现在我大概明白 Git 的重要作用是帮助我们管理整个软件开发过程。一个项目往往会不断修改，如果没有版本管理，很容易出现不知道代码改了什么、什么时候改的，甚至修改出错以后无法恢复的问题。Git 可以完整地保存每一次修改记录，使我们能够查看历史版本，也可以在出现问题时回退到之前的状态。

另外，在多人合作开发时，Git 的作用更加明显。不同的人可以分别修改代码，再通过分支和合并等方式将修改整合起来，而规范的提交信息又能让其他成员快速知道每一次修改的内容。再配合统一的版本号规范，整个项目的开发过程会更加清晰、有序。

因此，我认为学习 Git 是在学习一种规范的软件开发和协作方式。即使是个人项目，Git 也可以帮助我们保留修改记录、尝试不同方案；而在团队开发中，Git 更是代码协作和项目管理的重要工具。日后我将更多使用git进行工作学习。
